# BUG-152 — Los modales del admin se centran en la página, no en la pantalla

- **Zona:** admin / ui
- **Prioridad:** media
- **Estado:** en revisión
- **Asignado:** opencode
- **Rama:** `fix/tanda2-ui`
- **Fecha:** 2026-10-19

## Descripción
Los modales del panel de operadores (mensajes al propietario, edición de
locales, etc.) aparecían centrados en la tarjeta o en la página, no en la
pantalla. Al abrirlos con la página desplazada podían quedar fuera de la vista.
BUG-130 ya corrigió el mismo patrón en `.ruta`, pero en el admin seguía
ocurriendo.

## Causa
Los modales se renderizan **dentro de `.ops-card`**. En `paneles.css` esa
tarjeta tiene:

```css
.ops-content > .ops-card {
  animation: pn-aparecer 520ms var(--pn-ease-out) both;
}
```

Con `animation-fill-mode: both`, al terminar la animación el navegador conserva
el último keyframe. Como `pn-aparecer` solo define `from`, el valor final de
`transform` queda como `matrix(1, 0, 0, 1, 0, 0)` —una matriz identidad, no
`none`—. Un `transform` distinto de `none` convierte la tarjeta en *containing
block* de los descendientes `position: fixed`, así que el overlay deja de medir
el viewport y mide la tarjeta.

Medido en un banco de pruebas con el CSS real: el overlay medía **734×1511 px**
(alto de la tarjeta) en un viewport de 800×600.

## Solución
Cambiar `both` por `backwards` en las animaciones de entrada de
`paneles.css` (`pn-aparecer` y `pn-subir`), igual que se hizo con `.ruta` en
BUG-130. Con `backwards` la animación se sigue viendo igual, pero al terminar
el `transform` vuelve a `none` y la tarjeta deja de ser bloque contenedor.

Selectores corregidos: `.ops-kpis > *`, `.op-kpi-grid > *`, `.ops-hero`,
`.ops-grid-8-4 > *`, `.ops-grid-2 > *`, `.ops-content > .ops-card`,
`.op-panel`, `.dash-chart`, `.ops-feed > *` y `.ops-bar i`.

## Validación
Banco de pruebas con `paneles.css`, `ops.css` y `App.css` reales:

- Antes: overlay `x=28, y=1559, w=734, h=1511` (dentro de una tarjeta de
  1511 px), con `transform: matrix(1,0,0,1,0,0)` en `.ops-card`.
- Después: overlay `x=0, y=0, w=790, h=600` (viewport de 800×600; 790 por la
  barra de scroll) y se mantiene en `0,0` con scroll 0, 600 y 1200.

- `npm test`: 309/309.
- `npm run build`: correcto.
