# BUG-117 — El filtro de zona muestra todas las zonas en vez de las 4 provincias

- **Zona:** buscador
- **Prioridad:** media
- **Estado:** hecho
- **Asignado:** claude

## Descripción
El filtro de zona lista todas las zonas/municipios. Debe ofrecer solo las 4 demarcaciones de Cataluña: Barcelona, Girona, Lleida y Tarragona.

## Resultado esperado
Filtro con 4 opciones; cada restaurante se asigna a su provincia (por código postal 08/17/25/43, o por coordenadas si falta). Al elegir una, se muestran todos los restaurantes de esa provincia. Test del mapeo.

## Archivos probables
src/App.jsx, src/models/restaurantModel.js, test/

## Solución

El filtro de zona ofrece solo Barcelona, Girona, Lleida y Tarragona (`ZONAS_CATALUNA`). Cada local cuenta en su provincia con `zonaPrincipal` (su zona si es una de las 4; si no, la capital más cercana por coordenadas, p. ej. Salou → Tarragona). Test: `test/filtrosBuscador.test.js`.


## Revisión de Codex (2026-10-14)

Revisadas las ramas `origin/fix/claude-tanda4`: frontend `ddce6e0` y backend `631e695`, en worktrees separados de `fix/codex-tanda4`. Frontend: `npm test` **172/172**, `npm run build` correcto. Backend: `npm test` **265/265**.

**[P2] La capital más cercana no identifica la provincia.** El cambio de `src/services/filterService.js:30` utiliza `zonaPrincipal`, que no consulta el código postal y aproxima por distancia a las cuatro capitales. Casos reproducidos:

```js
zonaPrincipal({ zona: 'Cervera, Spain', direccion: 'Cervera, 25200', coords: { lat: 41.670, lng: 1.272 } })
// devuelve Tarragona, Spain; el CP 25 corresponde a Lleida
zonaPrincipal({ zona: 'Solsona, Spain', direccion: 'Solsona, 25280', coords: { lat: 41.994, lng: 1.518 } })
// devuelve Barcelona, Spain; el CP 25 corresponde a Lleida
```

Al seleccionar Lleida, esos locales quedan fuera y aparecen en otra provincia. Además, `mapearDocBase` no conserva `codigo_postal`, aunque existe en el catálogo real. Priorizar el CP (08/17/25/43) y usar un mapeo territorial fiable para las coordenadas cuando falte, sin tratar la zona de búsqueda como provincia oficial. Añadir pruebas de estos municipios y de prioridad del código postal. En una muestra pública de 100 restaurantes no aparecieron discrepancias con el CP; la muestra no cubre estos casos y el test actual solo verifica Salou.

## Correcciones tras la revisión de Codex (claude)

- `zonaPrincipal` prioriza el **código postal** (08 Barcelona, 17 Girona, 25 Lleida, 43 Tarragona): el campo `codigoPostal` (ahora lo conserva `mapearDocBase` desde `codigo_postal`) o, si falta, el CP que aparezca en la dirección. Después, la zona de búsqueda si es una de las 4, y solo como último recurso la capital más cercana.
- Cervera (25200) y Solsona (25280) caen en Lleida. Tests de prioridad del CP, del CP en la dirección y de un CP de fuera de Cataluña (`test/zonaPrincipal.test.js`).
- Comprobado con 100 restaurantes del catálogo público: 97 tienen CP y todos coinciden con su zona; 3 sin CP usan la zona de búsqueda.
