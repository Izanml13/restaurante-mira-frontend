# BUG-109 — Dashboard de restaurante desborda el ancho móvil de 390 px

- **Zona:** dashboard/móvil
- **Prioridad:** media
- **Estado:** en revisión
- **Asignado:** codex

## Pasos para reproducir
1. Abrir dashboard de restaurante con datos válidos en viewport 390×844.
2. Observar tarjetas, controles de cabecera y ancho total del documento.
3. Intentar acceder a Factura/Exportar liquidación sin desplazamiento horizontal de toda la página.

## Resultado esperado
Tarjetas y controles se ajustan a 390 px; únicamente las tablas pueden tener scroll en su contenedor.

## Resultado actual
Documento de 845 px y tarjetas de 797 px; varios controles quedan fuera de pantalla.

## Notas / capturas
`src/App.css` .auth-pagina y `src/components/dashboard/dashboard.css` .op-hub-wrap/grids propagan el ancho intrínseco de las tablas por min-width automático. Fixture usa el wrapper real main.ruta/auth-pagina y datos completos del contrato. Confirmado por padre y subagente: `{viewport:390, documentWidth:845}`; captura `/tmp/tanda2-dashboard-desborde-390.png`. No es un fallo de tema de BUG-018.

## Solución

Causa reproducida a390px: min-width automático de grids/tables y margen inline negativo de sección ensanchaban el documento hasta845px (tarjetas797px). Archivos: Dashboard.jsx y dashboard.css. Se permite encoger wrappers/hijos grid/gráficos, se restringe tabla/chips al contenedor y se elimina margen negativo externo. Tablas siguen con scroll propio, sin ocultar el contenido de la página. Verificación con componentes reales y datos del agregador backend: ancho documento390 a viewport390, en claro/oscuro; escritorio1280 sin desbordamiento. Captura /tmp/tanda3-dashboard-390.png. npm test158/158 y npm run build pasan. Cambio visual reversible verificado en navegador; sin test de implementación CSS. Pendiente: revisión.
