# BUG-111 — POST /points/review da puntos sin una reseña real

- **Zona:** puntos
- **Prioridad:** alta
- **Estado:** en revisión
- **Asignado:** claude

## Descripción
Detectado por Codex en BUG-014 (P1). El endpoint de puntos por reseña premia sin comprobar que exista una reseña del usuario, y crear una reseña también llama a reviewPoints: posible doble recompensa. La tool de IA reviewPoints tiene el mismo problema.

## Resultado esperado
Solo se dan puntos una vez por reseña real del usuario (ligado al id de la reseña, idempotente). El endpoint suelto no permite premiar sin reseña. Tests de: sin reseña → 4xx; reseña propia → puntos una vez; repetir → sin puntos extra.

## Archivos probables
backend mira-api/src/modules/points (routes.js, service.js: reviewPoints), modules/reviews, modules/ai/tools.js y handlers/points.js

## Solución
- **Causa:** `reviewPoints(uid)` abonaba 20 puntos sin mirar nada, y `POST /v1/points/review` (sin body) la exponía a cualquier usuario: bastaba con llamarlo en bucle para sumar puntos. Además, cada reseña nueva daba 20 puntos, así que escribiendo reseñas del mismo restaurante se acumulaban sin límite. Ni la web ni la app móvil usan ese endpoint.
- **Cambio (backend):**
  - `points/service.js`, `reviewPoints(uid, reviewId)`: en una transacción comprueba que la reseña existe (si no, 404) y es del usuario (si no, 403), y abona 20 puntos **una sola vez por usuario y restaurante** con un movimiento de id fijo `resena_{uid}_{restauranteId}`. Si ya existe, devuelve `puntos: 0, yaOtorgados: true`.
  - `POST /v1/points/review` exige `{ reviewId }` (zod).
  - `POST /v1/reviews` pasa el id de la reseña creada.
  - La tool de IA `createReview` ahora también da los puntos por la misma vía (antes por el chat no se daban).
  - `docs/api.md` §6.10 actualizado.
- **Cambio (frontend):** `pointsApi.review(reviewId)` envía el id. Nadie la usa; se deja coherente con el contrato nuevo.
- **Verificación:** test nuevo `mira-api/test/puntosResena.test.js` con 5 casos: sin reseña → 400; reseña inexistente → 404; reseña ajena → 403; crear reseña da 20 y reintentar no suma; 3 reseñas del mismo sitio dan 20 y una de otro sitio suma 20 más. Con el código anterior fallan los 5. Backend 234 ok.
- **Pendiente:** `mobile/src/services/api.js` sigue con `review()` sin `reviewId` (no se usa en la app). Si algún día se usa, recibirá 400.
- **Despliegue:** en cualquier orden; ningún cliente depende de este endpoint.
