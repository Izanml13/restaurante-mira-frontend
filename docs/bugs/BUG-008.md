# BUG-008 — Resolver incidencia en el panel admin con popup de confirmación

- **Zona:** admin
- **Prioridad:** media
- **Estado:** hecho
- **Asignado:** codex

## Descripción
Ahora se resuelve una incidencia con un solo clic.

## Resultado esperado
Al pulsar «Resolver» se abre un modal con los campos «Propuesta de resolución», «Solución» y «Encargado» (obligatorios). Al confirmar se marca como resuelta y se guardan esos datos; con «Cancelar» no cambia nada.

## Archivos probables
src/components/dashboard/AdminPanel.jsx o src/components/Admin.jsx (localizar las incidencias)

## Solución
Causa: los tres accesos admin resolvían con un clic y el endpoint solo actualizaba el estado. Archivos frontend: `Admin.jsx`, `ops/OpsIncidencias.jsx`, `ops/OpsDashboard.jsx`, nuevo `ResolverIncidenciaModal.jsx`, `styles/resolverIncidencia.css`, `services/incidenciaApi.js`, nuevo `services/incidenciaResolucion.js`, traducciones `i18n/es.js`, `ca.js`, `en.js` y `test/incidenciaResolucion.test.js`. El modal exige propuesta, solución y encargado; cancelar no llama a la API, errores mantienen el modal y se bloquea el doble envío. Backend autorizado en el repo independiente `codex-bugs-backend`, rama homónima: `contactos/routes.js`, `contactos/service.js`, `ai/handlers/admin.js`, `ai/tools.js` y `test/contactosResolucion.test.js`. Se validan y guardan los tres campos junto al estado en una sola actualización.

Verificación: `npm test` y `npm run build` pasan. Rama: `fix/codex-bugs`.

Verificación adicional: frontend 143 tests; backend 184 tests, incluidos guardado, campos obligatorios, espacios vacíos y permisos. El backend no dispone de script build. Prueba aislada del modal en navegador: campos vacíos bloquean envío, cancelar deja el estado intacto, confirmar devuelve los tres campos; revisión a 390 px en oscuro. El cambio requiere desplegar también el backend.
