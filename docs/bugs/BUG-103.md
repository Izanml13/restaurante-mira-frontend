# BUG-103 — Quitar de la lista de espera oculta la reserva aunque falle el servidor

- **Zona:** reservas
- **Prioridad:** media
- **Estado:** en revisión
- **Asignado:** claude

## Pasos para reproducir
1. Estar apuntado a la lista de espera de un restaurante y abrir Mis reservas.
2. Simular 500 o desconexión en `DELETE /v1/espera/:id`.
3. Pulsar «Quitar».
4. Recargar la vista con la conexión recuperada.

## Resultado esperado
Conservar la fila y mostrar error/reintento si el servidor no confirma la eliminación.

## Resultado actual
La fila desaparece sin aviso pese al fallo; vuelve a aparecer al cargar los datos del servidor.

## Notas / capturas
`src/components/Reservas.jsx`: el handler hace `.catch(() => {})` y filtra la fila incondicionalmente. `src/services/mejorasApi.js` usa DELETE. Ejecución del handler real con salir rechazando Error("500"): estado [{id:"lista-1"}] termina en []. Ejecutar `node docs/bugs/reproducciones/usuario.mjs .`. Distinto del reset de scroll de BUG-006.

## Solución
- **Causa:** el botón «Quitar» de `Reservas.jsx` hacía `esperaApi.salir(e.id).catch(() => {})` y después quitaba la fila siempre, aunque el servidor hubiera fallado.
- **Cambio:** nuevo `handleSalirEspera(e)` en `Reservas.jsx`, con el mismo patrón que `handleCancelar`. Solo quita la fila si `salir` termina bien; si falla, la fila se queda y el mensaje aparece en la alerta de error de la página.
- **Verificación:** test nuevo `test/esperaQuitar.test.js`, que ejecuta el manejador real extraído de `Reservas.jsx`. Con la API fallando la fila sigue y se muestra «500»; con la API bien la fila desaparece. `npm test` 154 ok, build ok. La vista real necesita sesión.
- **Nota:** los textos «Quitar», «Esperando» y «¡Mesa libre! Reservar» siguen fijos en castellano; se traducen en BUG-112.
