# BUG-130 — Los modales y desplegables se centran en la página y no en la pantalla

- **Zona:** ui-global
- **Prioridad:** alta
- **Estado:** en revisión
- **Asignado:** claude
- **Rama:** fix/errores-ui-web

## Pasos para reproducir
1. Abrir una página con scroll (p. ej. landing larga o ficha).
2. Bajar por la página y abrir un modal o desplegable.

## Resultado esperado
El modal/desplegable queda centrado respecto a la ventana (pantalla), siempre visible.

## Resultado actual
Aparecen centrados respecto al documento: se ven a media altura o fuera del viewport si la página está scrolleada.

## Notas / capturas
Hallazgo del usuario (afecta a varios modales). Causa típica: `position: absolute` en vez de `fixed` (o contenedor con `transform`). Buscar modales comunes en `src/components/` y unificar el patrón; toca a muchos componentes, hacer cambio transversal mínimo.

## Solución
- **Causa:** `src/styles/motion.css`, `.ruta { animation: ruta-entra .5s var(--ease-expo) both; }`. El `fill-mode: both` deja aplicado el keyframe final (`translate: 0 0`) **al terminar** la animación. Un `translate` distinto de `none` convierte `<main className="ruta">` en bloque contenedor de sus descendientes `position: fixed`, así que los overlays `.op-modal-overlay`, `.ops-modal-overlay` y `.dash-modal-overlay` (todos `position: fixed; inset: 0` con centrado) se dimensionaban respecto a `<main>` (toda la página) y no a la ventana: el modal salía a media altura y había que bajar para verlo. La ficha (`.modal-fondo`) no se veía afectada porque se renderiza fuera de `<main>`.
- **Cambio:** fill-mode `both` → `backwards` en `.ruta`. El estado final es idéntico (`translate: 0 0` == `none`), pero al terminar la animación `.ruta` ya no tiene `translate` y deja de crear bloque contenedor.
- **Verificación:** `npm test` (238 ok), `npm run build` correcto.
