# BUG-104 — Los accesos de canje e historial de puntos de Mi cuenta están cruzados

- **Zona:** cuenta/puntos
- **Prioridad:** media
- **Estado:** en revisión
- **Asignado:** claude

## Pasos para reproducir
1. Iniciar sesión y abrir Mi cuenta.
2. Pulsar «Canjear puntos».
3. Volver y pulsar «Historial de puntos».

## Resultado esperado
Canjear puntos abre el panel con descuentos; Historial de puntos abre la tabla de historial con filtros.

## Resultado actual
Canjear puntos navega a `#/puntos/historial`, sin controles de canje. Historial de puntos navega a `#/puntos`.

## Notas / capturas
`src/components/Cuenta.jsx`: href de `points.history` y `points.redeem` invertidos. `App.jsx` monta HistorialPuntos para /puntos/historial; solo contiene LedgerTable, mientras PuntosDashboard monta DiscountPanel. Extracción ejecutada: Historial de puntos => #/puntos; Canjear puntos => #/puntos/historial; destino sin DiscountPanel. Ejecutar `node docs/bugs/reproducciones/usuario.mjs .`. Fallo de destino independiente de BUG-019 (idioma) y BUG-015 (invitaciones).

## Solución
- **Causa:** en `Cuenta.jsx` los dos enlaces tenían las etiquetas cambiadas: el que iba a `#/puntos` (que tiene `DiscountPanel` para canjear) decía «Historial de puntos», y el que iba a `#/puntos/historial` (solo `LedgerTable`) decía «Canjear puntos».
- **Cambio:** se intercambian las etiquetas y se mantienen las rutas. «Canjear puntos» sigue siendo el botón principal y lleva a `#/puntos`; «Historial de puntos» es el secundario y lleva a `#/puntos/historial`.
- **Verificación:** `npm test` 150 ok. El script de Codex `docs/bugs/reproducciones/usuario.mjs` lee `Cuenta.jsx` y ahora da «Canjear puntos => #/puntos» y «Historial de puntos => #/puntos/historial» (su aserción del bug deja de cumplirse). La vista real necesita sesión.
