# BUG-137 — Verificar el correo lleva a la página de restablecer contraseña

- **Zona:** auth (web)
- **Prioridad:** alta
- **Estado:** hecho
- **Asignado:** codex

## Pasos para reproducir
1. Registrarse con un correo nuevo.
2. Abrir el enlace del correo de verificación.

## Resultado esperado
Se verifica el correo (`applyActionCode`) y se muestra «Correo verificado».

## Resultado actual
Abre la web en `#/restablecer` y pide una nueva contraseña.

## Notas
Hallazgo del usuario. Causa probable: en Firebase Auth, la URL de acción de las plantillas apunta a `#/restablecer` para todas las acciones. `Restablecer.jsx` solo extrae `oobCode` y no mira `mode` (`verifyEmail` / `resetPassword` / `recoverEmail`). Arreglo propuesto: un gestor de acciones que bifurque por `mode` (verifyEmail → `applyActionCode` y mensaje; resetPassword → el formulario actual). Revisar también qué envía la app móvil.

## Solución
Implementado en `fix/BUG-137-verificar-correo`, desde `origin/main` (`3a1fbc6`), en el worktree propio `codex-BUG-137`.

- `src/services/accionesCorreo.js`: selección pura por mode y lectura de parámetros tanto en search como en el hash. verifyEmail no entra en el reset; resetPassword y ausencia de mode conservan el comportamiento anterior; acciones desconocidas se rechazan.
- `Restablecer.jsx`: verifyEmail llama a `verificarCorreo`, que usa `applyActionCode(auth, oobCode)`, sin exigir sesión. Muestra Correo verificado con enlaces a login e inicio; errores traducidos para código inválido/usado, caducado y otros fallos. Comparte la promesa por código entre efectos de StrictMode y cambios de idioma para no consumir dos veces el enlace.
- Reset conserva el formulario y confirmPasswordReset. recoverEmail muestra un mensaje específico con acceso a soporte, sin aplicar recuperación ni pedir contraseña (alcance mínimo solicitado).
- Textos con useT en es, ca y en. En web y app, registro y reenvío de verificación usan una continuación al inicio; solo los correos de recuperación de contraseña mantienen /#/restablecer. Se distingue la URL de continuación (`actionCodeSettings.url`) del handler de acciones de las plantillas de Firebase; no se ha cambiado la consola.
- Tests: `test/accionesCorreo.test.js` (12), con funciones puras, componente real transformado con esbuild y React/Firebase simulados (incluye repetición de efectos, éxito/error, reset con/sin mode, tres idiomas), y servicios reales de auth web/app con Firebase simulado para registro/reenvío/continuación y applyActionCode.
- Validación: `npm test` **288/288**, `npm run build` correcto, lint móvil correcto; comprobación dirigida de sintaxis JS de mobile/src/services/authApi.js con tsc correcta. Sin typecheck integral porque mobile no tiene tsconfig.json. Sin envío de correos reales ni prueba con código de producción: queda para la prueba conjunta tras revisión y despliegue.
- Integración directa en main autorizada posteriormente por Izan, tras la validación anterior. Implementación en 14974f2; BUG-133 a BUG-136 quedan fuera de esta entrega.
