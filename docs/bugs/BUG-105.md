# BUG-105 — Exportar liquidación de Este mes incluye tickets de otros meses

- **Zona:** dashboard/fiscal
- **Prioridad:** media
- **Estado:** en revisión
- **Asignado:** codex

## Pasos para reproducir
1. Tener un ticket del mes actual y otro del mes anterior en el restaurante.
2. Abrir el dashboard y seleccionar «Este mes».
3. Pulsar «Exportar Liquidación» y abrir el CSV.

## Resultado esperado
El CSV contiene únicamente los tickets del mes seleccionado.

## Resultado actual
El archivo contiene tickets de ambos meses, aunque se presenta como liquidación del mes actual.

## Notas / capturas
`src/components/dashboard/Dashboard.jsx`, handleExportLiquidacion: filtro `f.startsWith(m) || true` siempre verdadero. Prueba reproducible desde la raíz frontend: `node docs/bugs/reproducciones/paneles.mjs . ../codex-tanda2-backend`. Extrae las funciones reales y simula únicamente la descarga, sin API remota ni escrituras. La función exportó un ticket antiguo de 2025-01-13 junto al actual. El subagente también descargó un CSV de octubre que incluía septiembre con datos simulados.

## Solución

Causa reproducida: el filtro de mes usaba || true y exportaba siempre todas las filas. Además fechaDeTicket no reconocía createdAt ISO de la API. Archivos: Dashboard.jsx, dashboardDatos.js, fiscal/fiscalReal.js, test/dashboardDatos.test.js. CSV y factura comparten filtro de periodo; fecha conocida se normaliza desde fecha, ISO, Date o Timestamp. Fechas desconocidas no se atribuyen a un periodo. Tests: mes actual frente al anterior, año/90 días y formatos de fecha. Verificación: npm test155/155 y npm run build pasan. Pendiente: revisión; sin cambio backend.

Caso de límite de mes añadido: timestamp UTC 2026-09-30T22:30:00Z corresponde a 1 de octubre en Europe/Madrid y se incluye en octubre. La fecha timestamp se normaliza en la zona del negocio.
