# BUG-101 — La ficha inventa plazas libres cuando falla la consulta de disponibilidad

- **Zona:** reservas
- **Prioridad:** media
- **Estado:** en revisión
- **Asignado:** claude

## Pasos para reproducir
1. Abrir una ficha de restaurante.
2. Bloquear la petición `GET /v1/reservations/availability` en las herramientas del navegador, o simular un error de red/500.
3. Seleccionar una fecha futura y una hora (p. ej. mañana, 13:00).

## Resultado esperado
Mostrar disponibilidad desconocida y un error/reintento, sin afirmar cuántas plazas están libres.

## Resultado actual
La ficha muestra «4 de 4 plazas libres» (el límite configurado) y mantiene «Reservar» habilitado.

## Notas / capturas
`src/services/reservaApi.js`, catch de `getDisponibilidad`, devuelve ocupadas=0/libres=limite ante cualquier fallo. `RestaurantDetail.jsx` presenta ese fallback como disponibilidad real. Reproducido con componente real y consulta simulada rechazando Error, manteniendo el resto de datos/API. Confirmación DOM: `.det-disponible` = "4 de 4 plazas libres", botón Reservar habilitado. Captura: `/tmp/tanda2-disponibilidad-error.png`. No se envió una reserva. No duplica ninguna ficha 001–021.

## Solución
- **Causa:** el `catch` de `getDisponibilidad` (`reservaApi.js`) devolvía `{ ocupadas: 0, libres: limite }`, es decir, el aforo entero libre, y la ficha lo pintaba como dato real.
- **Cambio:** si falla la consulta, `reservaApi.js` devuelve `{ limite, ocupadas: null, libres: null, desconocida: true }`. `RestaurantDetail.jsx` muestra en gris «No hemos podido comprobar las plazas libres. Puedes intentar reservar igualmente: te confirmaremos si hay sitio.» (nueva clave `detail.disponibilidadDesconocida` en es/ca/en) y no lo trata como completo. «Reservar» sigue habilitado, porque el backend valida el aforo al crear la reserva. Estilo `.det-disponible.desconocida` en `detalle.css`.
- **Verificación:** test nuevo `test/disponibilidad.test.js` (fallo → `desconocida`, sin plazas inventadas; respuesta normal → sin cambios). `npm test` 152 ok, build ok. En el navegador con la API simulada, la respuesta normal sigue mostrando «14 de 20 plazas libres»; forzando el fallo de `/availability` sale el aviso gris de arriba en vez de «20 de 20».
