# BUG-106 — La exportación de liquidación pierde tickets cuando hay más de 20

- **Zona:** dashboard/fiscal
- **Prioridad:** alta
- **Estado:** en revisión
- **Asignado:** codex

## Pasos para reproducir
1. Tener 25 tickets de 100 € en un mismo mes para un restaurante.
2. Abrir su dashboard: facturación total 2500 €.
3. Exportar la liquidación del periodo y sumar las filas del CSV.

## Resultado esperado
25 tickets y total 2500 €, mediante dataset completo o paginación.

## Resultado actual
20 filas y total 2000 €; el archivo omite 5 tickets sin avisar.

## Notas / capturas
Backend `mira-api/src/modules/dashboard/service.js`, buildRestaurantAggregates: `ticketsRecientes` se limita a 20. Frontend `Dashboard.jsx`, handleExportLiquidacion usa ese subconjunto como dataset completo. Prueba reproducible desde la raíz frontend: `node docs/bugs/reproducciones/paneles.mjs . ../codex-tanda2-backend`. Extrae las funciones reales y simula únicamente la descarga, sin API remota ni escrituras. Salida verificada: backend.stats.totalFacturacion=2500; ticketsRecientes.length=20; filasCSV=20. La factura real usa la misma fuente, pero su interfaz con 25 tickets queda por comprobar; esta ficha se sostiene en la reproducción del CSV. No duplica bugs fiscales previos del índice.

## Solución

Causa reproducida: datos completos de 25 tickets/2500 euros se exportaban desde ticketsRecientes, limitado a20; la consulta backend también limitaba a500. Archivos frontend: Dashboard.jsx, dashboardDatos.js, test/dashboardDatos.test.js, i18n/es.js/ca.js/en.js (solo nuevo aviso de API antigua). Backend: modules/dashboard/service.js, test/dashboardTicketsCompletos.test.js, docs/api.md. Contrato añade tickets completo; preview20 se conserva. CSV y factura real usan el completo filtrado; si falta no se genera un documento parcial y se muestra aviso traducido. Tests obligatorios:525 tickets,52500 euros, CSV y factura con525 filas; consulta HTTP sin tickets ajenos y403 para no propietario; respuesta antigua rechazada. Verificación: frontend158/158, build correcto y backend231/231. Backend primero, frontend después; sin nueva configuración de Render/Vercel. El dataset se sirve completo para un cambio mínimo; paginación por cursor recomendable si crece mucho el volumen. Pendiente: revisión y comprobación en staging.

Prueba adicional en navegador: panel real con fixture fiel de25 tickets; desactivar Datos simulados y abrir Factura produce25 líneas en la tabla del documento.
