# BUG-018 — Bugs visuales en modo oscuro y claro

- **Zona:** tema
- **Prioridad:** media
- **Estado:** en revisión
- **Asignado:** codex

## Descripción
Hay fallos visuales al cambiar entre modo oscuro y claro (sin detallar).

## Resultado esperado
Recorrer todas las vistas en ambos modos (escritorio y móvil 390 px) y corregir textos ilegibles, fondos que no cambian, colores fijos en vez de variables del tema, bordes invisibles, etc. Listar cada caso en la sección Solución.

## Archivos probables
src/App.css, src/styles/*.css, componentes con estilos inline

## Solución

Reproducción: capturas aisladas con componentes/markup reales y API simulada mostraban texto de racha claro sobre papel fijo claro en oscuro, filtro activo de mapa blanco sobre --verde-oscuro claro, JAM siempre oscuro y textos de énfasis ops de verde oscuro sobre fondos oscuros.

Casos corregidos (solo CSS): 1) App.css: racha/ruleta y bocadillo usan --papel; días/badges de recompensa usan nuevos tokens claros/oscuros, puntos usan --verde. 2) mapa.css: filtro activo usa --primary-container, manteniendo texto blanco legible. 3) jam.css: paleta de fondo/panel/borde/texto/acentos y campos del formulario heredan tema, sin color-scheme oscuro forzado. 4) ops.css: acentos verdes/azules/error con valores legibles en oscuro. 5) dashboard.css: enlaces usan token de texto de acento y botones de acción/fecha mantienen blanco sobre verde de acción. 6) tokens.css: aliases de --text-primary/secondary y radios que se referenciaban sin definir; fondos/textos semánticos de recompensa.

Recorrido: landing/buscador/cards, login, registro, recuperar/restablecer, privacidad, contacto, negocio, favoritos, reservas, cuenta, mensajes, mapa, descubrir, ficha/carta, puntos, historial, invitar, dashboard restaurante, ops, MIRASI, racha, ruleta y documento fiscal. 108 combinaciones únicas de 27 vistas x 2 temas x 2 anchos (1280/390). Fixtures de componentes reales con datos simulados; no cuentas ni reservas reales. Capturas de los casos principales inspeccionadas; documento fiscal mantiene su papel blanco para impresión/exportación. Recorrido de estados básicos, no de todos los posibles modales/errores/datos remotos. Matriz temporal: /tmp/tanda2-matriz-visual.json; muestras /tmp/tanda2-*-390.png.

Verificación: 148 tests frontend y npm run build pasan; diff sin errores. También se comprobó en la muestra de mensajes que Marcar todo como leído desaparece y No leídos pasa a 0. No se modifican Header.jsx, JSX, textos ni CSS content. Pendiente: revisión y aceptación con datos reales.
