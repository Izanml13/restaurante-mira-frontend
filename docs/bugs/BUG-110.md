# BUG-110 — La búsqueda de cabecera Ops no actualiza Reservas Globales al pulsar Enter

- **Zona:** admin/ops
- **Prioridad:** media
- **Estado:** en revisión
- **Asignado:** codex

## Pasos para reproducir
1. Abrir Reservas Globales en Ops con reservas de dos clientes, Ana y Beto.
2. Escribir «Ana» en «Buscar en el panel», en la cabecera.
3. Pulsar Enter.
4. Comparar con pulsar el botón «Buscar» dentro de la sección.

## Resultado esperado
Enter recarga la consulta y muestra solo las reservas de Ana.

## Resultado actual
Los inputs cambian pero siguen apareciendo Ana y Beto. El botón Buscar de la sección sí reduce la tabla a Ana.

## Notas / capturas
`src/components/ops/OpsPanel.jsx`: Enter llama setSeccion(reservas); si la sección ya está abierta, no se remonta. `OpsReservas.jsx`: efecto de qInicial modifica q pero no llama cargar. Reproducción UI con servicio simulado que filtra q correctamente: Enter mantiene el texto «2 reservas»; Buscar local muestra «1 reservas». Confirmada por padre y subagente. No duplica idioma de BUG-019.

## Solución

Causa reproducida en navegador: Enter solo cambiaba sección; cuando Reservas Globales ya estaba abierta, no se cargaba la consulta. Archivos: OpsPanel.jsx y OpsReservas.jsx. La cabecera comunica consulta enviada y revisión; efecto carga explícitamente esa q, incluso repetida o vacía, sin remontar el panel/perder filtro de estado. Un identificador descarta respuestas antiguas. Búsqueda local conserva botón/Enter. Sin traducir o mover textos (BUG112). Verificación UI con API simulada que filtra q: Ana1, Beto1, Beto repetido1, vacío2; antes Enter mantenía2. npm test158/158 y npm run build pasan. No añadido test que replique hooks; interacción real de componentes verifica el flujo. Pendiente: revisión.
